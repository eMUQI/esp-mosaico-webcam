# 视频处理与缓冲区管理

[English README](../README.md) | [中文 README](../README.zh-CN.md)

本说明面向固件开发者，介绍摄像头采集、JPEG 编码、USB 视频传输和本地显示之间的数据流，以及缓冲区的借用和归还规则。像素处理加速器（PPA）负责画面的旋转、缩放和格式转换。

```text
H2 Camera -> BSP UYVY frame -> PPA RGB565 640x480 -> JPEG hardware
                                  |                    |
                          borrowed RGB565 slot     3 bounded slots
                                  |                    |
                           low-priority PPA       UVC get / return
                                  |                    |
                             LVGL image          USB transfer copy
```

## 摄像头采集与 JPEG 编码

`capture_task` 独占摄像头的操作权限。创建、打开、启动、取帧、归还、断电控制（PWDN）和清理均在该任务内执行。正常情况下最多借用一个摄像头帧；PPA 处理完成后立即归还。JPEG 编码和本地显示不持有摄像头数字视频接口（DVP）的缓冲区。

JPEG 槽位状态为 `FREE → WRITING → READY → BORROWED → READY/FREE`。采集任务只选择空闲或最旧的就绪槽位，不能写入正在被 USB 借用的槽位。USB 只借用最新有效槽位，USB Device UVC 组件将数据复制到自身的传输缓冲区后调用归还回调。旧帧不排队发送；可重复发送最近一帧，超过 500 ms 的旧画面不再发送。

所有槽位状态和应用状态由同一互斥锁保护。锁仅覆盖索引和状态更新，JPEG 编码、PPA 和图像处理在锁外执行。JPEG 内存由 ESP-IDF 专用分配器分配，以满足直接内存访问（DMA）的对齐要求。

每次切换隐私状态、开始或停止 USB 视频流时，状态代次 `epoch` 递增。采集任务开始处理一帧时记录当前代次，发布时重新检查，丢弃旧代次的帧。已经借给 USB 的帧允许完成复制，避免覆盖正在读取的内存。

隐私黑帧在启动时由同一硬件 JPEG 编码器生成，尺寸为 640×480，之后保持不可变。视频帧和黑帧均检查 JPEG 起始标记（SOI）、结束标记（EOI）及容量。USB 回调不编码图像，也不等待摄像头。

## 本地预览与界面

采集任务从两个归一化 RGB565 槽位中选择未借给预览的槽位。JPEG 编码结束后，最多借出一个槽位给预览。有效图像区域、已应用的 USB 视频旋转角度和 `epoch` 元数据与图像一同提交，不从后续设置或采集帧推算。

预览任务通过通知唤醒，用 PPA 选取有效区域并旋转、缩放至后台显示缓冲区，PPA 完成后立即归还原始槽位。随后在 LVGL 锁内交换前后台缓冲区指针、更新图像描述符并标记图像重绘，不复制整帧。

预览邮箱只保留一个待处理帧。邮箱忙时立即丢弃本次预览，采集和 USB 视频传输不等待本地显示。处理前和显示前分别核对隐私状态及 `epoch`，所有丢弃分支均归还借用槽位。

归一化缓冲区仅在源尺寸或旋转变化时清零并回写黑边；构图不变时，PPA 只覆盖有效区域。预览与 USB 视频保留相同的有效画面。SC101IOT 默认以 1280×720、25 FPS 采集，USB 描述符声明 MJPEG 640×480、25 FPS；预览随新采集帧更新。

安装方向校正在归一化阶段应用，X 轴校正在 PPA 事务内修正 SC101IOT 的左右反向。本地预览以同一归一化缓冲区为输入，在第二次 PPA 处理中进行屏幕方向补偿和可选镜像，等比缩放完整画面至 480×360 预览区域，比例不符时居中留边。

### 显示提交与关屏

界面状态每秒刷新 4 次。`webcam_display` 关闭 BSP 的 LVGL 适配器，在同一显示任务中运行 Espressif 的 `esp_lv_present` 和 LVGL 定时器。

LVGL 使用单个 32 行 PSRAM 绘制缓冲区，关闭分块异步复制，避免在复制完成前复用同一存储区域。显示提交器使用两个完整合成缓冲区承接局部更新，再通过防撕裂信号（TE）调度整帧传输。BSP 固定面板为原生 0° 扫描方向，QSPI 单次传输容量覆盖完整帧，并启用直接 PSRAM DMA。

关屏时，OLED 亮度归零，本地预览停止，触摸检测继续运行。顶层覆盖对象接收首次唤醒触摸，避免该次触摸触发按钮。

### 设置保存

设置通过互斥锁传给维护任务。维护任务每秒检查一次设置变更，将设置写入带版本号的非易失性存储（NVS）数据块；读取时校验版本、长度和字段范围。隐私状态不存入 NVS，每次上电默认开启。

## 姿态检测与本地显示方向

转向任务通过 BSP 初始化 BMI270 惯性测量单元（IMU），每 100 ms 读取一次加速度。方向判定要求主轴加速度至少为 0.65 g，且至少为另一轴的 1.15 倍，连续 3 次同向读数后确认方向。弱读数、非有限值和对角线区域读数会中断候选方向的累计。

已确认的目标方向保持到新目标确认；显示忙时，下次采样继续尝试切换。任务优先级为 4，低于采集与 USB 视频任务，高于预览图像任务。IMU 初始化失败时清理资源并在 5 秒后重试；读取失败时取消候选方向、降低重试频率，显示保持原方向。

预览任务只在取出帧描述和提交显示时取得邮箱锁，耗时的 PPA 处理在锁外执行。帧描述及屏幕角度先复制到任务栈；提交前在同一锁下复核角度，丢弃转向过程中生成的旧方向画面。已经接收通知的任务会等待邮箱锁并取出对应帧，避免转向占锁时丢失唯一通知，导致借用槽位无法归还。采集任务以零等待方式提交预览，USB 视频任务不取得邮箱锁。

方向切换通过 `webcam_display_set_rotation()` 请求显示任务完成旧提交，再重建提交器的旋转状态。显示任务重新取得绘制缓冲池地址并绑定 LVGL，随后标记整个屏幕重绘。旋转失败时，重新绑定恢复后的缓冲区；缓冲区不可用或提交器故障时，暂停绘制，避免访问已释放的内存。

调用旋转接口时不持有显示锁。原始触摸坐标由同一提交器映射；方向切换后清除旧输入并等待触摸释放，保留当前预览直到新帧提交。屏幕关闭期间不切换方向。方向切换不修改隐私状态、自动关屏计时或 NVS 设置。

### 画面方向变换

面板变换按 BSP 的实际矩阵组合，PPA 使用逆时针角度。摄像头相对屏幕的基准采用 BSP 预览示例的 270° 安装旋转。预览先抵消该帧已经应用的 USB 视频旋转，再叠加安装角及面板的逆变换。X 轴和 Y 轴安装镜像的奇偶性参与角度组合，不能直接把屏幕角度作为摄像头角度。

PPA 只读取归一化缓冲区中的有效画面区域，不将 USB 黑边再次旋转和缩放。有效图像按 1/16 精度等比缩小至预览区域，使用偶数输出偏移居中留边，保留完整视野。每个后台缓冲区在有效区域尺寸或角度变化时清理黑边，避免残留旧内容。

USB 视频旋转独立控制电脑视频方向，本地预览不随该设置侧转。IMU 不修改 USB 视频旋转设置，也不重新协商 USB 格式。方向和触摸检查步骤见[测试指南](../TESTING.md#设备测试)。

## 错误与恢复

- 摄像头创建或打开失败：向 USB 主机发送黑帧，每隔 1 秒重试。
- 不完整帧：BSP 已归还该帧，应用记录错误后直接取下一帧，不重新初始化摄像头。
- 采集超时：在无借用帧时优先重启视频流，并跳过 5 帧预热；重启失败才清理资源并重新检测模块。其他采集错误连续出现 3 次后执行清理。
- 归还帧失败：保留所有权并重试归还，禁止直接重启摄像头或释放仍被借用的 DMA 缓冲区；USB 视频输出使用黑帧。持续驱动错误可能需要重新上电。
- PPA 处理或 JPEG 编码失败：记录错误，不发布无效帧，后续采集继续重试。
- 初始化失败：UART 报错并保留运行，不进入反复重启循环。
- USB 视频流开始或停止：只更新 `epoch`，不分配帧缓冲区。设备枚举状态、视频传输状态和连接速度分别从 TinyUSB 查询。

USB 组件提交失败时会退回重试。USB 拔插与连续开关流的检查方法见[测试指南](../TESTING.md)。PPA 的阻塞调用和底层 DMA 故障恢复由 ESP-IDF 和 BSP 驱动负责。
